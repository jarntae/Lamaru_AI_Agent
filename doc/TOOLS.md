# Tool System

## 1. Purpose

Tools allow the Agent to interact with the development environment.

The Agent requests tools.
The Tool Manager validates and executes them.

## 2. Tool interface

Conceptually:

```python
class Tool:
    name: str
    description: str
    input_schema: dict
    permission: PermissionLevel

    async def execute(self, input):
        ...
```

### Terminal

- run_command

### Git

- git_diff
- git_log
- git_branch
- git_commit

## 4. Structured result

Every tool should return structured data:

```text
success
output
error
metadata
```

Avoid returning only unstructured strings where structured data is practical.

## 5. Permissions

Permission levels:

```text
ALLOWED
CONFIRMATION_REQUIRED
BLOCKED
```

## 6. Default policy

Safe read operations may be ALLOWED.

File deletion, destructive shell commands and other irreversible actions should require confirmation or be BLOCKED.

## 7. Terminal

Never assume a command is safe because it is generated by a model.

The terminal tool must enforce policy before execution.

## 8. Workspace boundary

File tools should normally be restricted to the configured workspace.

Access outside the workspace should require explicit configuration.

## 9. Tool timeouts

Every external operation must have a timeout.

A hung command must not freeze the entire Agent session.

## 10. Output limits

Tool output should have configurable maximum sizes.

Large command output should be truncated or summarized rather than blindly inserted into context.

## 11. MCP

MCP may expose selected tools externally.

Do not expose dangerous internal operations automatically.

MCP tools must use the same permission system as native tools where possible.
